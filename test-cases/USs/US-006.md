# História de Usuário

EU COMO Administrador do Sistema e Responsável por Segurança e Governança no IAM,  
GOSTARIA DE gerenciar centralizadamente os usuários, atribuir e revogar papéis RBAC (LEITOR, EDITOR, ADMIN) e realizar exclusão controlada de contas com salvaguardas de proteção,  
PARA QUE a integridade de acesso à plataforma seja mantida, prevenindo auto-bloqueios, exclusão acidental de contas essenciais do sistema e acesso não autorizado a recursos privilegiados.  

# Escopo

- Proteção rigorosa de rotas administrativas ('/api/iam/users') exigindo a permissão 'admin:all' validada via JWT e middleware de autorização, retornando HTTP 403 Forbidden para usuários não autorizados.
- Painel visual administrativo 'UsersManagementPage' com tabela paginada de usuários, métricas de contas ativas, exibição de papéis atribuídos e filtros de pesquisa.
- Atualização transacional de papéis ('PUT /api/iam/users/:id/roles') com limpeza e reinserção atômica em 'iam.user_roles' garantindo que o papel mínimo de LEITOR seja sempre preservado.
- Fluxo seguro de exclusão de usuários ('DELETE /api/iam/users/:id') com confirmação explícita via modal e remoção em cascata (FK Cascade) de permissões e vínculos no banco de dados.
- Regras de salvaguarda e imunidade protegendo contra auto-exclusão da conta autenticada e exclusão de contas demarcadas com a flag 'is_system_protected=true', bloqueando a operação tanto no frontend quanto no backend com HTTP 403 Forbidden.

# Não Escopo

- Integração federada com provedores externos corporativos (SAML 2.0 / Active Directory) nesta camada local de RBAC.
- Auditoria e rastreamento forense de logs de auditoria em SIEM externo em tempo real.
- Delegação temporária de privilégios de acesso com data de expiração programada por usuário.

# Critérios de Aceite

**CA01 - Atualização Transacional de Papéis RBAC de Usuário [Cobre: SC-001]**  
- **Dado** que o administrador autenticado possui a permissão 'admin:all' e acessa a 'UsersManagementPage'  
- **Quando** altera os checkboxes de permissões (LEITOR, EDITOR, ADMIN) de um usuário e envia a requisição 'PUT /api/iam/users/:id/roles'  
- **Então** o banco PostgreSQL deve executar uma transação atômica (DELETE e INSERT em user_roles)  
- **E** responder com 'HTTP 200 OK'  
- **E** disparar a invalidação de cache do React Query na chave ['admin', 'users']  

**CA02 - Bloqueio de Acesso Administrativo para Usuários sem Permissão [Cobre: SC-002]**  
- **Dado** que um usuário autenticado não possui a permissão 'admin:all'  
- **Quando** tentar acessar as rotas de gerenciamento de usuários '/api/iam/users'  
- **Então** o middleware de segurança deve rejeitar a requisição respondendo 'HTTP 403 Forbidden (Acesso Negado)'  
- **E** não deve expor a lista de usuários ou papéis  

**CA03 - Exclusão de Usuário Permitida com Confirmação e Cascata [Cobre: SC-003]**  
- **Dado** que o administrador solicita a exclusão de um usuário comum desprotegido  
- **Quando** confirmar a revogação no modal de confirmação e disparar 'DELETE /api/iam/users/:id'  
- **Então** o PostgreSQL deve remover o registro de 'iam.users' com exclusão em cascata em 'iam.user_roles'  
- **E** responder com 'HTTP 200 OK' e atualizar a tabela na interface  

**CA04 - Bloqueio de Auto-Exclusão e Contas Protegidas do Sistema [Cobre: SC-004]**  
- **Dado** que o administrador tenta excluir a própria conta conectada ou um usuário marcado com 'is_system_protected=true'  
- **Quando** a ação for submetida no frontend ou atingir o backend  
- **Então** o sistema deve bloquear imediatamente a exclusão e retornar status 'HTTP 403 Forbidden (Usuário Protegido)'  
- **E** manter a conta do usuário totalmente preservada no banco de dados  

**CA05 - Garantia de Papel Mínimo de Leitor na Atribuição [Cobre: SC-005]**  
- **Dado** que o administrador desmarca todos os papéis opcionais de um usuário  
- **Quando** salvar as alterações de permissões  
- **Então** o sistema deve assegurar que o papel base 'LEITOR' permaneça atribuído  
- **E** não permitir que nenhum usuário ativo fique sem papéis de acesso
