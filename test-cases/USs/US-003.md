# História de Usuário

EU COMO Mecanismo de Inteligência Artificial e Worker Assíncrono do nlp-service,  
GOSTARIA DE consumir eventos de materiais do RabbitMQ, extrair metadados e métricas, realizar chunking hierárquico estruturado de markdown, gerar embeddings vetoriais de 768 dimensões com cache Redis e indexar os vetores via pgvector HNSW,  
PARA QUE os documentos técnicos estejam prontamente disponíveis para busca híbrida ponderada de altíssima precisão e recuperação semântica no motor RAG.  

# Escopo

- Consumo assíncrono e resiliente de mensagens da fila 'nlp.processamento' via RabbitMQ com validação de payload JSON e descarte seguro (channel.nack sem requeue) para mensagens inválidas ou corrompidas.
- Tratamento diferenciado por tipo de evento: exclusão atômica em 'busca.indices_busca' com propagação em cascata para 'material_chunks' no evento 'material.excluido', ou ingestão completa para 'material.criado' / 'material.atualizado'.
- Extração de metadados e cálculo de métricas de legibilidade (palavras, bytes) com upsert automático em 'busca.indices_busca' alimentando colunas tsvector para busca textual lexical BM25/FTS.
- Chunking semântico e estruturado de Markdown baseado em hierarquia de cabeçalhos (#, ##, ###) com limite de 400 palavras por chunk e janela deslizante de overlap de 50 palavras para seções extensas.
- Estratégia híbrida de geração de embeddings com verificação prévia de cache Redis ('emb:sha256'), geração local de vetores de 768 dimensões com normalização L2 (1.0), gravação no Redis com TTL de 24 horas e persistência em lote no PostgreSQL com índice pgvector HNSW.

# Não Escopo

- Extração e OCR de texto a partir de arquivos binários pesados (PDFs escaneados ou imagens embutidas) nesta fila de eventos.
- Retreinamento online ou fine-tuning de modelos de embeddings neurais em tempo de execução.
- Geração de respostas de linguagem natural com LLM generativa, que é de responsabilidade exclusiva do chat-service.

# Critérios de Aceite

**CA01 - Ingestão e Processamento Completo de NLP com Cache Hit [Cobre: SC-001]**  
- **Dado** que uma mensagem de 'material.criado' ou 'material.atualizado' chega na fila 'nlp.processamento'  
- **Quando** o worker valida o payload, executa o chunking estruturado e localiza os vetores de 768d no cache Redis ('emb:sha256')  
- **Então** o sistema deve reutilizar os vetores em cache, executar Batch INSERT em 'material_chunks' com índice HNSW, confirmar a mensagem via 'channel.ack(msg)' e publicar o evento 'material.enriquecido'  
- **E** atualizar o índice lexical tsvector em 'busca.indices_busca'  

**CA02 - Geração e Normalização de Embeddings com Cache Miss [Cobre: SC-003]**  
- **Dado** que os chunks do documento não possuem vetores previamente cacheados no Redis  
- **Quando** o modelo de NLP gera os embeddings locais de 768 dimensões  
- **Então** o sistema deve aplicar a normalização L2 (norma euclidiana = 1.0), armazenar os vetores no Redis com TTL de 24 horas e persistir os chunks indexados no PostgreSQL  
- **E** emitir 'channel.ack(msg)' e publicar 'material.enriquecido' na exchange do RabbitMQ  

**CA03 - Expurgo e Limpeza Vetorial em Eventos de Exclusão [Cobre: SC-002]**  
- **Dado** que uma mensagem válida com evento 'material.excluido' é consumida pela fila  
- **Quando** o nlp-service processar o identificador do material  
- **Então** deve executar DELETE em 'busca.indices_busca', provocando a remoção em cascata de todos os chunks associados na tabela 'material_chunks'  
- **E** confirmar o processamento via 'channel.ack(msg)' e publicar notificação de expurgo em 'material.enriquecido'  

**CA04 - Descarte Seguro de Mensagens Malformadas e Corrompidas [Cobre: SC-004]**  
- **Dado** que uma mensagem recebida na fila 'nlp.processamento' possui JSON corrompido ou schema inválido  
- **Quando** o parser do worker interceptar a falha de integridade  
- **Então** o daemon deve rejeitar a mensagem executando 'channel.nack(msg, false, false)'  
- **E** descartar a mensagem sem reenfileirar (evitando poison message loop)  
- **E** registrar log estruturado de erro de parsing  

**CA05 - Segmentação de Markdown com Overlap em Seções Extensas [Cobre: SC-001, SC-003]**  
- **Dado** que o documento técnico submetido possui seções contendo mais de 400 palavras  
- **Quando** o 'MarkdownChunker' segmentar o texto com base nos cabeçalhos Markdown (#, ##, ###)  
- **Então** deve criar sub-chunks contínuos aplicando janela deslizante de overlap de exatamente 50 palavras  
- **E** preservar a integridade contextual entre as fronteiras dos blocos de texto
