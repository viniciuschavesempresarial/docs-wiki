# História de Usuário

EU COMO Engenheiro de DevOps, SRE ou Desenvolvedor de Software,  
GOSTARIA DE contar com uma esteira automatizada de CI/CD via GitHub Actions e Self-Hosted Runner que execute validação rigorosa de build, testes unitários e de integração (Jest e RTL), emissão automática de tags de versão LTS e rollback automático para a última versão estável em caso de falhas,  
PARA QUE a plataforma Docs-Wiki seja entregue com zero downtime, alta confiabilidade e garantia de recuperação imediata sem intervenção manual em caso de regressões.  

# Escopo

- Execução contínua em Self-Hosted Runner disparada por push na branch 'staging' orquestrando o job 'build-test-deploy' com injeção segura de segredos de ambiente (.env).
- Etapas determinísticas de compilação de workspaces ('npm ci & npm run build'), validação estática de manifestos Docker ('docker compose config'), execução de suíte de testes backend (88 Jest) e frontend (19 React Testing Library).
- Geração automática e renovação de certificados SSL locais na pasta 'certs/' e provisionamento orquestrado de containers via 'docker compose up -d'.
- Publicação automatizada de tags de release LTS ('v1.0.{run}-lts-{date}') com assinatura anotada no repositório Git ('git tag -a' e 'git push origin') após sucesso completo da esteira.
- Mecanismo de autorrecuperação e rollback automático (Job 'rollback') acionado em caso de qualquer falha na esteira, identificando a última tag LTS estável ('git checkout $LATEST_LTS'), reconstruindo a aplicação e restaurando o ambiente operacional anterior.

# Não Escopo

- Provisionamento de infraestrutura bare-metal ou instâncias de nuvem via Terraform/OpenTofu nesta esteira de aplicação.
- Testes de carga distribuídos e testes de estresse em escala de produção durante o gatilho padrão de push.
- Aprovação manual interativa com múltiplos gates de governança externos (ITIL) fora do workflow do GitHub Actions.

# Critérios de Aceite

**CA01 - Build, Testes e Publicação de Tag LTS em Deploy Bem-Sucedido [Cobre: SC-001]**  
- **Dado** que novos commits são enviados para a branch 'staging'  
- **Quando** o runner do GitHub Actions concluir com 100% de sucesso o build, os 88 testes Jest e os 19 testes RTL  
- **Então** a esteira deve subir os containers via 'docker compose up -d', calcular e criar a tag 'v1.0.{run}-lts-{date}' e dar push na tag de release  
- **E** marcar o status da execução como 'Deploy LTS Concluído com Sucesso'  

**CA02 - Disparo de Rollback Automático para Última Versão Estável em Caso de Falha [Cobre: SC-002]**  
- **Dado** que ocorre uma falha em qualquer etapa de compilação, validação de Docker ou quebra de testes automatizados  
- **Quando** a esteira interceptar o status de erro no job de build  
- **Então** o runner deve acionar imediatamente o job de rollback automático, consultar as tags LTS estáveis e executar 'git checkout $LATEST_LTS'  
- **E** reconstruir a versão estável e executar 'docker compose up -d'  
- **E** garantir a continuidade do serviço sem manter containers quebrados em produção  

**CA03 - Validação de Configuração Docker e Certificados SSL [Cobre: SC-001]**  
- **Dado** que a esteira inicia a preparação do ambiente de execução  
- **Quando** validar a integridade dos serviços pelo comando 'docker compose config'  
- **Então** deve emitir ou renovar os certificados SSL na pasta 'certs/' antes da inicialização dos daemons  
- **E** assegurar que o tráfego HTTP/HTTPS do NGINX opere com criptografia TLS válida
