# História de Usuário

EU COMO Leitor, Pesquisador ou Desenvolvedor na plataforma Docs-Wiki,  
GOSTARIA DE pesquisar materiais através de busca híbrida ponderada (combinando busca lexical BM25 e busca semântica vetorial pgvector), aplicar filtros facetados e solicitar sumarização contextual gerada por IA (Gemini),  
PARA QUE eu possa localizar documentos de alta relevância técnica em milissegundos e obter sínteses executivas diretas a partir do acervo indexado.  

# Escopo

- Endpoint de pesquisa 'GET /api/v1/search' protegido por limitação de taxa no NGINX (api_limit: 20 req/s) com suporte a paginação (page, limit) e filtros facetados (tags, autor, categoria).
- Mecanismo de busca híbrida ponderada no PostgreSQL combinando consulta lexical full-text (tsvector @@ plainto_tsquery com peso 0.3) e busca semântica vetorial pgvector (1 - embedding <=> query com peso 0.7) com trigramas fuzzy (pg_trgm).
- Cache de vetores de busca no Redis ('emb:sha256') para acelerar a vetorização de termos de consulta recorrentes de 768 dimensões.
- Modo de navegação e listagem padrão quando o termo 'q' estiver vazio, retornando os documentos mais recentes ordenados por data de atualização com scores neutros.
- Sumarização opcional orientada por IA ativada pelo parâmetro 'summarize=true', recuperando os top 4 chunks mais relevantes e enviando prompt estruturado para a API do Google Gemini (temperatura 0.3) para compor o campo 'ai_summary'.

# Não Escopo

- Treinamento de modelos de linguagem generativos próprios dentro da infraestrutura local.
- Suporte a operadores booleanos complexos avançados (NOT, NEAR) não compatíveis com a sintaxe padrão do PostgreSQL Full Text Search.
- Streaming de resposta de sumarização via Server-Sent Events (SSE) nesta rota síncrona de busca.

# Critérios de Aceite

**CA01 - Busca Híbrida Ponderada com Sumarização IA Ativada [Cobre: SC-001]**  
- **Dado** que o usuário envia uma consulta com termo 'q' válido e o parâmetro 'summarize=true'  
- **Quando** a API processa a busca híbrida (0.3 BM25 + 0.7 Vetorial) e localiza documentos relevantes  
- **Então** o sistema deve recuperar os top 4 chunks mais relevantes, invocar a API Gemini (temp: 0.3) para gerar a síntese e responder com 'HTTP 200 OK'  
- **E** retornar a lista ranqueada 'results', 'total', 'page', 'limit' e a síntese no campo 'ai_summary'  
- **E** renderizar no frontend os DocumentCards com badges de relevância e a caixa de resposta da IA  

**CA02 - Bloqueio por Excesso de Requisições na Busca [Cobre: SC-002]**  
- **Dado** que um cliente ou script automatizado dispara requisições em volume superior ao limite da API  
- **Quando** a taxa de chamadas ultrapassar o limite de 20 req/s configurado no NGINX ('api_limit')  
- **Então** o gateway deve rejeitar as requisições excedentes retornando status 'HTTP 429 Too Many Requests'  
- **E** incluir o cabeçalho 'Retry-After' sem executar consultas no banco de dados  

**CA03 - Navegação e Listagem sem Termo de Busca [Cobre: SC-003]**  
- **Dado** que o usuário acessa a busca sem fornecer o parâmetro de texto 'q'  
- **Quando** a requisição atingir o endpoint de busca  
- **Então** o PostgreSQL deve executar consulta direta na tabela 'indices_busca' aplicando filtros facetados e ordenação por data decrescente  
- **E** retornar os itens com 'hybrid_score = 1.0', 'text_score = 0' e 'ai_summary = null'  

**CA04 - Busca Híbrida Ponderada sem Sumarização IA [Cobre: SC-004]**  
- **Dado** que o usuário pesquisa com termo 'q' com 'summarize=false' ou omitido  
- **Quando** a busca híbrida ponderada calcular o score composto (0.3 BM25 + 0.7 Vetor)  
- **Então** a API deve retornar status 'HTTP 200 OK' com os resultados ordenados por relevância e o campo 'ai_summary = null'  
- **E** não deve realizar chamadas para a API externa do Google Gemini  

**CA05 - Tolerância a Erros Tipográficos com Busca Fuzzy pg_trgm [Cobre: SC-001, SC-004]**  
- **Dado** que o usuário digita um termo de busca contendo pequenos erros de digitação (ex: 'arquitetura' digitado como 'arquitertura')  
- **Quando** o motor de busca executa a consulta com extensão 'pg_trgm' habilitada  
- **Então** o sistema deve localizar os documentos com base em similaridade trigramática  
- **E** combinar o resultado com os vetores semânticos no score final ponderado
